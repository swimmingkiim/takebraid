# Takebraid의 개발·시스템 설계 철학

상태: 초기 설계 / 2026-10-26

Takebraid의 목표는 촬영 원본을 이해하고, 사람이 검토·수정할 수 있는 좋은 첫 편집을 만드는 것이다.
품질은 멋진 데모 한 편보다 **핵심 장면 보존과 실제 수정 시간 절감**으로 판단한다.

## 1. 관측, 해석, 결정, 실행을 나눈다

‘화면의 에지가 줄었다’는 관측이고, ‘초점이 나갔다’는 해석이며, ‘이 부분을 제외한다’는 결정이다.
결정을 실제 영상으로 만드는 것은 실행이다. 이 네 가지를 한 모델 호출이나 함수에 섞지 않는다.

이 구분으로 임계값·편집 의도·모델을 바꿔도 원본 분석 전체를 다시 하지 않을 수 있다.
잘못 제외된 장면은 근거를 확인하고 복원할 수 있다. 모델 점수는 보정되기 전에는 확률이 아니다.

## 2. AI는 후보를 제안하고, 검증 가능한 코드가 실행을 통제한다

모델에는 행동과 장면의 의미를 묻는다. 시간 계산, 원본 범위 검증, 필수 장면 보존, 길이·순서 제약,
명령 실행은 일반 코드가 맡는다. 모델이 반환한 원본 ID·시간·설명은 신뢰 경계 밖의 입력이다.

같은 관측·설정·사용자 수정이 주어지면 같은 타임라인이 나오도록 계획기를 설계한다.
모델 추론 자체는 장치·백엔드에 따라 달라질 수 있으므로 응답과 모델 버전을 저장한다.
이를 전체 모델 실행의 완전한 재현성과 혼동하지 않는다.

## 3. 시간 정확성과 원본 보존이 먼저다

매력적인 자동 편집도 프레임이 어긋나거나 소리가 밀리면 쓸 수 없다. 원본은 정수 PTS와 유리수
time base로 가리키고, 출력 프레임 시간과 구분한다. 프록시에서 찾은 위치를 원본으로 되돌리는
매핑은 독립적으로 검증한다. 파일 수정·삭제 없이 타임라인에서만 제외한다.

## 4. 모듈형 단일 애플리케이션으로 시작한다

Python 패키지 하나와 로컬 작업 폴더로 시작한다. 도메인 로직은 순수 코드로, FFmpeg·모델·저장소·UI는
어댑터로 둔다. 처음부터 서버 여러 개, 분산 큐, 플러그인 마켓, 별도 벡터 DB를 만들지 않는다.

여러 실제 사용처가 생기기 전에는 추상 인터페이스도 필요한 만큼만 만든다. 작업 중단·재개는 우선
단계별 결과 파일과 원자적 저장으로 해결한다. 프로파일링과 사용 요구가 서비스 분리를 정당화할 때
그 경계를 추출한다.

## 5. 분석은 모델에 독립적이고, 편집 의도는 데이터로 표현한다

모델명에 종속된 이벤트·품질 스키마를 만들지 않는다. 편집 의도와 장르 프로필은 버전이 있는 설정으로
표현한다. 같은 원본에서 과정형·제품형·여행형을 비교할 때 분석 결과를 재사용한다.

처음에는 로컬 모델 하나만 연결해도 된다. 두 번째 실제 구현 전에는 범용 플러그인 프레임워크를 만들지
않는다. 모델을 설치하지 않은 경우 기능 축소를 명확히 알린다.

## 6. 불확실함을 보존한다

정적인 화면이 촬영 대기라는 보장은 없다. 의도적인 팬을 흔들림으로 오해할 수도 있다.
`keep / exclude / review / unknown`을 구분하고, 근거가 부족하면 무리하게 제외하지 않는다.
모든 중요한 행동이 흔들린 화면에만 담겼다면 그 장면을 보존하는 정책을 허용한다.

모든 영상을 같은 강도로 자동 처리하지 않는다. 검증된 결함 유형부터 자동화를 허용하고,
문맥 의존 판단은 검토와 사용자 수정 데이터를 통해 개선한다.

## 7. 작은 완성 흐름을 반복해서 출시한다

첫 수직 기능은 ‘짧은 원본 입력 → 정확한 구간 목록 → 원본 재생·미리보기’다.
그다음 품질 표시, 구간 선별, 여러 원본 구성 순으로 연결한다. 동작하지 않는 기능의 CLI 이름을
먼저 채우지 않는다. 각 단계의 완료 조건은 `roadmap.md`에서 확인한다.

기본 CI는 GPU·모델 다운로드 없이 빠르게 돈다. 미디어 통합 검증과 모델 품질 평가는 별도 계층으로
둔다. 공개 예제의 성공뿐 아니라 실패 사례와 평가 세트의 편차를 기록한다.

## 8. 로컬 우선과 오픈소스 이용 조건을 제품 구조에 반영한다

기본 입력 영상과 분석 결과는 로컬에 둔다. 원격 모델 사용은 사용자가 선택하고 전송 범위를 확인한
경우에만 허용한다. 사용자 수정 로그도 자동 업로드하지 않는다.

자체 코드는 Apache-2.0으로 공개한다. 외부 코드·모델 가중치·데이터·미디어 바이너리는 각각 조건을
검토한다. 특정 모델의 비상업적 조건이 기본 설치 전체에 숨어 들어오지 않도록 한다.

## 지금 채택한 기술적 선택

| 선택 | 이유 | 다시 검토할 시점 |
|---|---|---|
| Python 3.11+ / src 패키지 구조 | 영상·모델 생태계, 가벼운 핵심 패키지 | 실제 배포·성능 자료가 쌓일 때 |
| CLI부터 구현 | 작은 전체 흐름을 검증하기 쉬움 | 검토 UI를 만드는 M4 |
| 로컬 JSON 아티팩트 | 검사·재현·도구 연동이 쉬움 | 프로젝트 크기 측정 후 인덱스가 필요할 때 |
| 정수 PTS + 유리수 시간 | VFR·비정수 fps·음수 시작 시각 처리 | 변경보다 변환 규칙 확장이 필요 |
| 먼저 촬영 순서를 보존 | 과정의 인과 관계를 덜 훼손 | 재배열의 개선 효과가 입증될 때 |
| 모델을 필수 의존성에서 분리 | 작은 설치, 장치 선택, 라이선스 관리 | 원칙 유지, 어댑터만 확장 |

구체적인 구조와 대안의 비용은 [architecture.md](architecture.md) 및 [ADR](adr/0001-local-modular-core.md)에
기록한다. 설계를 바꿀 때는 이유와 검증 근거를 남긴다.
